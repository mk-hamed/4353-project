# Assignment 4: Service Management and Wait-Time Estimation
## Toby Vu

I updated QueueSmart's Service Management module to store services in PostgreSQL instead of the A3 in-memory service array. The implementation supports creating, retrieving, and updating service records while preserving the frontend's existing API format. The Service table stores a generated service ID, name, description, expected duration, priority level, and open/closed status. Database constraints protect required fields, length limits, allowed values, and case-insensitive name uniqueness. All user-supplied values are passed to parameterized SQL queries.

I preserved the shared wait-time calculation and updated the queue module's service lookups to await database results. Wait time remains the user's position multiplied by the service duration in minutes. The existing API uses `id`, `durationMin`, and `priority`; these map to the database columns `serviceId`, `expectedDuration`, and `priorityLevel`. This keeps the frontend compatible and gives the queue module a consistent service representation. I also connected the service write routes to the existing JWT authentication middleware so that only verified administrators can create or update services.

The work includes a shared connection module, a versioned migration command, an optional seed command that preserves existing records, a safe example configuration, and isolated database test schemas. The original application has no service deletion operation, so closing a service remains the way to stop new joins without removing records referenced by queues or history.

### Service table design

```sql
CREATE TABLE IF NOT EXISTS "Service" (
  "serviceId" INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(100) NOT NULL CHECK (name = btrim(name) AND length(name) > 0),
  description VARCHAR(500) NOT NULL CHECK (description = btrim(description) AND length(description) > 0),
  "expectedDuration" INTEGER NOT NULL CHECK ("expectedDuration" BETWEEN 1 AND 480),
  "priorityLevel" VARCHAR(6) NOT NULL CHECK ("priorityLevel" IN ('low', 'medium', 'high')),
  status VARCHAR(6) NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'closed')),
  CHECK ("serviceId" > 0)
);
CREATE UNIQUE INDEX IF NOT EXISTS service_name_unique ON "Service" (lower(name));
```

Service has no outgoing foreign keys. Queue should reference `"Service"("serviceId")`; the final Queue and History relationships require team agreement.
